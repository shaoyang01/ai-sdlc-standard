# Specs Run Metadata and Archive/Cleanup Policy

> **Reference**: `${AI_SDLC_STANDARD_HOME}/ai-sdlc/specs-run-metadata-and-archive.md`

## Purpose

This file supplements `${AI_SDLC_STANDARD_HOME}/ai-sdlc/specs-run-lifecycle.md`. `specs/` is a run-level artifact, not a requirement-level artifact. This file defines:

- `specs_run_id` metadata and manifest recording
- Lifecycle states (created → active → business_domain_synced → archived / superseded / cleaned)
- Archive and cleanup gating rules
- Library-driven requirements without specs

This applies to projects where both `legacy_speckit` and `new_rail_sdlc` may exist. Library-driven / Direct Implementation may have no specs; this file must not require specs for all requirements.

## Specs Run Identity

| Field | Description |
| --- | --- |
| `specs_run_id` | Unique identifier for one pipeline run |
| `requirement_id` | Parent requirement |
| `feature_id` | Feature directory identifier |
| `rail` | `legacy_speckit` or `new_rail_sdlc` |
| `generated_by` | Skill or pipeline that generated the run |
| `source_mode` | `speckit_driven`, `library_driven`, `hybrid` |
| `lifecycle` | Current lifecycle state |
| `current_status` | `current`, `stale`, `superseded`, `archived`, `cleaned` |
| `created_at` | Run creation timestamp |
| `last_updated_at` | Last modification timestamp |

Rules:

- `specs_run_id` must be unique. Suggested format: `specs-{requirement_id}-{feature_slug}-{timestamp}`.
- Same `requirement_id` may have multiple `specs_run_id`.
- Same `specs_run_id` must have consistent rail. Rail consistency within run is enforced.
- `feature_id` is not `requirement_id`.
- `specs_run_id` is recorded in manifest, not expressed via directory naming.
- No filename-versioned artifacts to express specs run versions.

## Rail Consistency Within Run

- All artifacts within one specs run (`spec.md`, `plan.md`, `tasks.md`, `route.md`, `implementation.md`, `workflow-status.md`, `debug-guide.md`, `observability.md`) must be generated by the same rail.
- `legacy_speckit` run must not be taken over by `new_rail_sdlc` mid-run.
- `new_rail_sdlc` run must not mix in legacy Skill outputs.
- Different specs runs may use different rails.
- Rail inconsistency within a run is BLOCKED and must route to reconcile.

## Manifest Fields

Manifest is the lifecycle authority. `workflow-status.md` is only a machine-side snapshot and is not status authority.

```yaml
business_domain_sync:
  required: true / false
  mode: none | speckit_driven | library_driven | hybrid
  source_of_truth:
    - "<source>"
  pipeline_sync_executed: true / false
  library_sync_executed: true / false
  duplicate_sync_guard: active
  current_sync_owner: sdlc-speckit-sync | library-driven-sync
  result: synced | proposal | not_required | blocked
  reason: "<reason>"

specs_runs:
  - specs_run_id: "<id>"
    requirement_id: "<req-id>"
    feature_id: "<feature>"
    rail: legacy_speckit | new_rail_sdlc
    generated_by: "<skill>"
    source_mode: speckit_driven | library_driven | hybrid
    lifecycle: created | active | business_domain_synced | archived | superseded | cleaned
    current_status: current | stale | superseded | archived | cleaned
    specs_path: "<path>"
    source_artifacts:
      - "<path>"
    business_domain_sync_status: pending | synced | proposal | not_required | blocked
    synced_business_domain_targets:
      - "<path>"
    archive_allowed: true / false
    cleanup_allowed: true / false
    archive_reason: "<reason>"
    cleanup_reason: "<reason>"
    created_at: "<timestamp>"
    last_updated_at: "<timestamp>"
```

If manifest and `workflow-status.md` conflict, manifest wins and `MANIFEST_DRIFT` is recorded.

## Lifecycle States

| State | Description |
| --- | --- |
| `created` | Specs run generated, not yet confirmed as current implementation reference. |
| `active` | Current implementation, review, and verification still reference this run. |
| `business_domain_synced` | Stable facts have been synced or explicitly determined `not_required`. This state is valid only when `business_domain_sync.result` is `synced` or `not_required`. If result is `pending`, `proposal`, or `blocked`, the specs run must remain `active`, `created`, or another non-cleanup-eligible state, and cleanup is not allowed. |
| `archived` | No longer active implementation reference; traceability preserved. |
| `superseded` | Replaced by another `specs_run_id` for same `requirement_id`. |
| `cleaned` | Run files removed; manifest retains metadata and audit trace. |

## Archive Policy

Archive allowed when:

- lifecycle is `business_domain_synced` or `superseded`.
- not active implementation reference.
- `business_domain_sync.result` is `synced` or `not_required`.
- no open Re-Gate / review / test blocking items depend on the specs run.
- source artifacts and traceability preserved in manifest.
- `synced_business_domain_targets` recorded when applicable.
- user or owner authorization exists when moving files.

Archive forbidden when:

- lifecycle `active`.
- `business_domain_sync.result` is `pending` / `proposal` / `blocked`.
- implementation / review / test still references the specs run.
- manifest missing `specs_run_id` metadata.
- rail inconsistency unresolved.
- unresolved source priority conflict.
- archive would break traceability.

Archive path suggestion: `specs/archive/{feature_id}/` or `specs/archive/{requirement_id}/{specs_run_id}/`. No filename-versioned artifacts.

## Cleanup Policy

Cleanup allowed when:

- specs run is `archived` or `superseded`.
- manifest retains complete `specs_run` metadata.
- `business_domain_sync.result` is `synced` or `not_required`.
- no audit/reconcile requires original files.
- owner confirms cleanup.
- source artifacts captured in manifest or durable reports.

Cleanup forbidden when:

- lifecycle `active`.
- `business_domain_sync` is `pending` / `proposal` / `blocked`.
- audit or reconcile still needs original specs files.
- implementation or verification evidence only exists in specs run files.
- manifest lacks `source_artifacts` / synced targets.
- cleanup requested for library_driven requirement that never had specs (nothing to cleanup).
- cleanup would delete `library/{requirement_id}/**`.
- cleanup would delete `.specify/business_domain/**`.

Cleanup removes or moves run-level specs files only. It must not delete library, business_domain, or manifest lifecycle trace.

## Library-Driven Requirements Without Specs

- Library-driven requirement may have no `specs_runs` entry.
- Missing specs is expected and must not block.
- No specs archive/cleanup required when specs never existed.
- `business_domain_sync` can still record `mode=library_driven`.
- Manifest may record `specs_runs: []` or omit `specs_runs` for that requirement.
- Library artifacts remain requirement-level durable workspace and are not subject to specs cleanup policy.

## Sync/Reconcile References

- `sdlc-speckit-sync` output must record `specs_run_id` or `feature_id` when specs exist.
- Library_driven without specs: record `requirement_id` and `sync_source_mode` only.
- `sdlc-speckit-code-doc-reconcile` uses `specs_run_id` in speckit_driven/hybrid to determine current/stale/superseded.
- Reconcile must not flag archived/cleaned specs as missing if manifest retains traceability.
- If specs files are cleaned, manifest metadata is the traceability source.

## Blocking Rules

- `specs_run_id` missing for speckit_driven direct sync
- rail inconsistency within specs run
- manifest missing lifecycle state
- active specs run requested for cleanup
- `business_domain_sync` pending / proposal / blocked
- open Re-Gate depends on specs run
- `source_artifacts` missing
- `synced_business_domain_targets` missing when result=synced
- workflow-status conflicts with manifest → MANIFEST_DRIFT
- cleanup would remove only copy of implementation/verification evidence
- cleanup attempts to delete `library/{requirement_id}/**`
- cleanup attempts to delete `.specify/business_domain/**`
- lifecycle `business_domain_synced` with result `proposal` or `blocked` is invalid
- lifecycle `business_domain_synced` with result `pending` is invalid
