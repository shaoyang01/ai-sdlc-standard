## Purpose

This file defines the companion artifact contract for the v2 single-rail lifecycle (Decision-044). Based on Project Type Profile, it determines whether each canonical node artifact (00-06) and the C03 Delivery Tail artifact (07) is required, optional, conditional, or not applicable for a requirement.

The matrix applies to requirement-level library artifacts under `library/{requirement_id}/`. There is no separate specs run track, sync source mode, or pipeline authority in v2: every requirement walks the same seven-node chain, and the Design Depth Decision (LIGHT / STANDARD / DEEP) only changes how much content a node artifact must carry, never whether a node exists.

## Project Type Profiles

| Profile | Typical Use |
| --- | --- |
| `backend-business-service` | Java backend, Dubbo/Spring services |
| `frontend-application` | React Native, web frontend |
| `admin-mixed-workflow` | Admin workflow, approval, import/export |
| `data-pipeline-etl` | Spark/Flink ETL, data pipeline |
| `library-shared-component` | Shared library, SDK, component |

Profile source: explicit user confirmation or project governance profile. If profile unknown, use conservative baseline or BLOCKED; do not silently skip required artifacts.

## Artifact Status Values

| Status | Description |
| --- | --- |
| `Produced` | Generated by this generation. |
| `Reused` | Reused existing current artifact. Must record `source_artifacts` and `freshness`. |
| `Not Applicable` | Not needed for this project type or requirement scope. Must record `reason` and project-type justification. |
| `Deferred` | Not generated now, must be completed before later Gate/Re-Gate. Must record `reason`, `accepted_by`, `verification_alternative`, `re_gate_required`. |

Prohibited: silent skip. Deferred without Accepted By. Deferred without Verification Alternative. Required artifact missing but Gate PASS. Not Applicable without project-type justification.

## Artifact Matrix

| Artifact (Node) | backend-business-service | frontend-application | admin-mixed-workflow | data-pipeline-etl | library-shared-component |
| --- | --- | --- | --- | --- | --- |
| `00 需求资料`（requirement-intake） | Required or Reused | Required or Reused | Required or Reused | Required or Reused | Required or Reused |
| `01 技术方案`（solution-design） | Required or Reused（API/RPC/MQ 契约章节按深度档位） | Required or Reused（路由/页面/API/mock 边界契约章节） | Required or Reused（API/页面/权限/流程流转契约章节） | Required or Reused（输入输出 schema/SQL 血缘/作业触发/connector-sink 契约章节） | Required or Reused（公共 API/导出接口/兼容性契约章节） |
| `02 方案审核`（solution-gate） | Required（adversarial_scan Finding Ledger + formal_verdict Gate 与设计深度裁决） | Same | Same | Same | Same |
| `03 任务规划`（task-planning） | Required（DEEP 时含实现前一致性审计） | Same | Same | Same | Same |
| `04 实现记录`（implementation） | Required when actual implementation produced; otherwise Not Applicable with reason | Same | Same | Same | Same |
| `05 代码审核`（code-review） | Required when actual implementation produced（方案缺口回流 solution-design） | Same | Same | Same | Same |
| `06 知识同步`（knowledge-sync） | Required（可输出 NO_CHANGE；契约/规则/checklist/schema 沉淀） | Required（UI 交互规则与接口形状沉淀） | Required（流程/权限规则沉淀） | Required（表结构/血缘/重放规则沉淀） | Required（公共 API 与兼容性规则沉淀） |
| `07 交付总结`（C03 Delivery Tail） | Required at manual git handoff（READY_FOR_MANUAL_GIT_HANDOFF 前） | Same | Same | Same | Same |

Rules:
- `02 方案审核` is the only conclusive Gate (PASS / FAIL / PASS_WITH_RISK) plus Design Depth Decision (`decision_status = DECIDED` 才可进入实现；`BLOCKED_UNKNOWN` 阻塞)。
- `05 代码审核` closure 结论（closed / blocked / risk_accepted）与 `06 知识同步` decision（NO_CHANGE / APPLY_LOCAL / PROPOSAL_ONLY / BLOCKED_CONFLICT）不是 Gate。
- `07 交付总结` 不映射节点能力，不输出 Gate。

## Contract Types

In v2, contract artifacts are content sections of the `01 技术方案` (solution-design) artifact rather than a separate specs-run companion track. They may include: API contract, RPC contract, MQ producer / consumer contract, route / page contract, permission contract, workflow transition contract, trigger contract, SQL lineage contract, input/output schema contract, public API contract, exported interface contract, compatibility contract, mock/real data boundary contract.

## Skip / Defer Records

```yaml
artifact_matrix:
  project_type_profile: "<profile>"
  artifacts:
    - path: "<path>"
      node: 00-需求资料 | 01-技术方案 | 02-方案审核 | 03-任务规划 | 04-实现记录 | 05-代码审核 | 06-知识同步 | 07-交付总结
      requirement_level: required | optional | conditional | not_applicable
      status: Produced | Reused | Not Applicable | Deferred
      reason: "<reason>"
      accepted_by: "<owner>"
      verification_alternative: "<alternative>"
      re_gate_required: yes / no
      source_artifacts: ["<path>"]
      freshness: current | stale
      owner: "<owner>"
```

Rules:
- Required/conditional artifact Deferred must have `accepted_by` (Deferred without Accepted By → BLOCKED).
- Required/conditional artifact Deferred must have `verification_alternative` (Deferred without Verification Alternative → BLOCKED).
- Required/conditional artifact Not Applicable must have project-type justification.
- Missing required artifact without valid record → BLOCKED.

## Gate / Admission Rules（准入规则）

In v2, only solution-gate (formal_verdict) outputs a conclusive Gate; node admission checks are executed deterministically by the LOOP runtime (generation, current revision, Gate result, Design Depth Decision, finding status). `sdlc-gate-runner` is retired. [RETIRED — C03-B]

**PASS**: all required artifacts Produced/Reused, OR Deferred with accepted_by + verification_alternative + re_gate_required, OR Not Applicable with valid project-type justification; Gate Result is PASS / PASS_WITH_RISK and `decision_status = DECIDED`.

**BLOCKED**: required artifact missing, Deferred without accepted_by, Deferred without verification_alternative, Not Applicable without project-type justification, profile unknown and no conservative baseline/user confirmation, artifact matrix absent, artifact status stale, source_artifacts missing for Reused, `decision_status = BLOCKED_UNKNOWN` at implementation entry, stale/forged Gate or depth decision used as admission basis, solution-gate two roles executed by the same Agent binding, PASS_WITH_RISK without accepted-risk evidence.

## Manifest Recording

```yaml
artifact_matrix:
  project_type_profile: "<profile>"
  profile_source: "<source>"
  status: complete | partial | blocked
  artifacts:
    - path: "<path>"
      node: "<node>"
      requirement_level: required | optional | conditional | not_applicable
      status: Produced | Reused | Not Applicable | Deferred
      reason: "<reason>"
      accepted_by: "<owner>"
      verification_alternative: "<alternative>"
      re_gate_required: yes / no
      source_artifacts: ["<path>"]
      freshness: current | stale
      owner: "<owner>"
  blocking_items:
    - "<item>"
  depth_decision: LIGHT | STANDARD | DEEP | BLOCKED_UNKNOWN
  gate_result: PASS | FAIL | PASS_WITH_RISK
```

- Manifest records matrix outcome, the Design Depth Decision and the solution-gate result.
- No filename-versioned artifacts (no filename-versioned artifacts). Stable paths only.
- `07 交付总结`（Delivery Tail）单独登记，不进入七节点 Artifact Index。

## Blocking Rules

- unknown project_type_profile
- artifact matrix missing
- required artifact missing
- required artifact Deferred without accepted_by
- required artifact Deferred without verification_alternative
- Not Applicable without project-type justification
- Reused without source_artifacts or freshness
- stale artifact used as current
- `02 方案审核` missing Finding Ledger reference or Design Depth Decision at implementation entry
- `decision_status = BLOCKED_UNKNOWN` at implementation entry
- solution-gate adversarial_scan / formal_verdict executed by the same Agent binding
- `04 实现记录` / `05 代码审核` missing when actual implementation produced
- knowledge-sync input contains stale revision or unclosed blocking finding
- `07 交付总结` missing at manual git handoff（READY_FOR_MANUAL_GIT_HANDOFF）
- workflow-status or pipeline snapshot treated as manifest authority
- filename-versioned artifacts used for companion artifacts
- Gate PASS with missing required artifact (must not allow)
