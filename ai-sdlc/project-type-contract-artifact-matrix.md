# Project-Type Contract Artifact Matrix

> **Reference**: `${AI_SDLC_STANDARD_HOME}/ai-sdlc/project-type-contract-artifact-matrix.md`

## Purpose

This file defines the companion artifact contract for the Plan stage. Based on Project Type Profile, it determines whether each companion artifact is required, optional, conditional, or not applicable.

Companion artifacts are specs run-level artifacts, not requirement-level library artifacts. This applies to `speckit_driven` and `hybrid` Plan stages that produce specs. `library_driven` without specs does not require specs companion artifacts; DocFlow library artifacts can serve as equivalent evidence.

## Project Type Profiles

| Profile | Typical Use |
| --- | --- |
| `backend-business-service` | Java backend, Dubbo/Spring services |
| `frontend-application` | React Native, web frontend |
| `admin-mixed-workflow` | Admin workflow, approval, import/export |
| `data-pipeline-etl` | Spark/Flink ETL, data pipeline |
| `library-shared-component` | Shared library, SDK, component |

Profile source: `.specify/project-governance-profile.yaml`, route artifact, or explicit user confirmation. If profile unknown, use conservative baseline or BLOCKED; do not silently skip required artifacts.

## Artifact Status Values

| Status | Description |
| --- | --- |
| `Produced` | Generated by this run. |
| `Reused` | Reused existing current artifact. Must record `source_artifacts` and `freshness`. |
| `Not Applicable` | Not needed for this project type or requirement scope. Must record `reason` and project-type justification. |
| `Deferred` | Not generated now, must be completed before later Gate/Re-Gate. Must record `reason`, `accepted_by`, `verification_alternative`, `re_gate_required`. |

Prohibited: silent skip. Deferred without Accepted By. Deferred without Verification Alternative. Required artifact missing but Plan Gate PASS. Not Applicable without project-type justification.

## Contract Types

Contract artifacts may include: API contract, RPC contract, MQ producer / consumer contract, route / page contract, permission contract, workflow transition contract, trigger contract, SQL lineage contract, input/output schema contract, public API contract, exported interface contract, compatibility contract, mock/real data boundary contract.

## Skip / Defer Records

```yaml
contract_artifact_matrix:
  project_type_profile: "<profile>"
  artifacts:
    - path: "<path>"
      artifact_type: "<type>"
      requirement_level: required | optional | conditional | not_applicable
      status: Produced | Reused | Not Applicable | Deferred
      reason: "<reason>"
      accepted_by: "<owner>"
      verification_alternative: "<alternative>"
      re_gate_required: yes / no
      source_artifacts: ["<path>"]
      freshness: current | stale
      owner: "<owner>"
```

Rules:
- Required/conditional artifact Deferred must have `accepted_by` (Deferred without Accepted By → BLOCKED).
- Required/conditional artifact Deferred must have `verification_alternative` (Deferred without Verification Alternative → BLOCKED).
- Required/conditional artifact Not Applicable must have project-type justification.
- Missing required artifact without valid record → Plan Gate BLOCKED.

## Plan Gate Rules

**PASS**: all required artifacts Produced/Reused, OR Deferred with accepted_by + verification_alternative + re_gate_required, OR Not Applicable with valid project-type justification.

**BLOCKED**: required artifact missing, Deferred without accepted_by, Deferred without verification_alternative, Not Applicable without project-type justification, profile unknown and no conservative baseline/user confirmation, contract artifact matrix absent, artifact status stale, source_artifacts missing for Reused, route.md missing when business_domain sync route is materialized, contracts/ missing when external/public interface exists.

## Manifest Recording

```yaml
contract_artifact_matrix:

  profile_source: "<source>"
  status: complete | partial | blocked
  artifacts:
    - path: "<path>"
      artifact_type: "<type>"
      requirement_level: required | optional | conditional | not_applicable
      status: Produced | Reused | Not Applicable | Deferred
      reason: "<reason>"
      accepted_by: "<owner>"
      verification_alternative: "<alternative>"
      re_gate_required: yes / no
      source_artifacts: ["<path>"]
      freshness: current | stale
      owner: "<owner>"
  blocking_items:
    - "<item>"
  plan_gate_result: PASS | PASS_WITH_RISK | BLOCKED
```

- Manifest records matrix outcome.
- No filename-versioned artifacts (no filename-versioned artifacts). Stable paths only.

## Library-Driven Relationship

- `library_driven` without specs does not require specs companion artifacts.
- DocFlow library artifacts can serve as equivalent evidence when no specs run exists.
- If library_driven later triggers speckit/hybrid plan, matrix applies to that specs run.
- Do not block library_driven sync because specs companion artifacts are absent.

## Blocking Rules

- unknown project_type_profile
- contract artifact matrix missing
- required artifact missing
- required artifact Deferred without accepted_by
- required artifact Deferred without verification_alternative
- Not Applicable without project-type justification
- Reused without source_artifacts or freshness
- stale artifact used as current
- contracts/ missing when public/external interface exists
- data-model.md missing when persistence/schema/domain model exists
- quickstart.md missing when verification requires runnable steps
- route.md missing when business_domain sync target is materialized
- workflow-status treated as manifest authority
- filename-versioned artifacts used for companion artifacts
- Plan Gate PASS with missing required artifact (must not allow)
