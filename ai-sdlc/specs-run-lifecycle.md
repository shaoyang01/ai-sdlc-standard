# Specs Run Lifecycle

> **Reference**: `${AI_SDLC_STANDARD_HOME}/ai-sdlc/specs-run-lifecycle.md`

## Purpose

Define `specs/` as a **run-level artifact**, not a requirement-level artifact. One Speckit flow / pipeline run generates one set of specs. The same `requirement_id` may have multiple specs runs over time.

## Run-Level Artifact

- **One run = one set of specs.** A single pipeline execution produces one `specs/{feature}/` directory.
- **Rail consistency within a run.** All artifacts in one specs run must be generated by the same rail (`legacy_speckit` or `new_rail_sdlc`). Mixing rails within one run (e.g., `specify` from legacy, `plan` from new-rail) is not allowed.
- **Multiple runs per requirement.** The same `requirement_id` can be associated with multiple specs runs across different branches, iterations, or rework cycles.
- **Rail diversity across runs.** Different runs for the same `requirement_id` may use different rails (e.g., legacy Speckit for the initial run, new-rail for a supplement).

## Specs Artifact Baseline

Regardless of rail, every specs run must be capable of producing these core artifacts:

| Artifact | Legacy Speckit | New-Rail SDLC |
| --- | :--: | :--: |
| `spec.md` | ✅ Required | ✅ Required |
| `clarification.md` | ✅ Optional | ✅ Optional |
| `plan.md` | ✅ Required | ✅ Required |
| `research.md` | ✅ Required or skipped | ✅ Required or skipped (Produced/Reused/Not Applicable/Deferred) |
| `data-model.md` | ✅ Required or skipped | ✅ Required or skipped |
| `contracts/` | ✅ Required or skipped | ✅ Required or skipped (project-type contract matrix) |
| `quickstart.md` | ✅ Required or skipped | ✅ Required or skipped |
| `tasks.md` | ✅ Required | ✅ Required |
| `checklists/` | ✅ Optional | ✅ Optional |

New-Rail may additionally produce enhanced artifacts:

| Artifact | Description |
| --- | --- |
| `route.md` | Domain route artifact (Route Type, Business Domain Targets, Entry Coverage Surface, Create-If-Missing Decision) |
| `implementation.md` | Implementation record with file changes and technical decisions |
| `workflow-status.md` | Machine-side workflow status snapshot (manifest is status authority) |
| `debug-guide.md` | Debug guide with reproduction steps and mock/real data switching |
| `observability.md` | Observability record with logging, metrics, analytics, and error state |

## Specs Metadata

Each specs run should record metadata. Recommended fields:

| Field | Description |
| --- | --- |
| `rail` | `legacy_speckit` or `new_rail_sdlc` |
| `generated_by` | Skill or pipeline that generated this run |
| `requirement_id` | Parent requirement identifier |
| `lifecycle` | `active`, `archived`, `superseded` |
| `business_domain_sync_status` | `synced`, `proposal`, `not_required`, `pending` |

## Specs Lifecycle

```
created → active → business_domain_synced → archived / superseded
```

- **created**: Specs artifacts generated by a pipeline run.
- **active**: Specs are the current implementation reference. Implementation, review, and verification reference them.
- **business_domain_synced**: Stable facts have been synced to `.specify/business_domain/**`. Specs may be archived after sync.
- **archived**: Specs are no longer the active reference. Archived specs may be kept for traceability or cleaned up.
- **superseded**: A newer specs run for the same `requirement_id` has replaced this run.

## Archive / Cleanup

After `business_domain_sync_status` is `synced`, specs may be archived or cleaned up:

- Archive: Move to `specs/archive/{feature}/` for traceability.
- Cleanup: Remove specs directory when no longer needed for audit or traceability.

Do not archive or cleanup specs while they are still the active implementation reference or while business_domain sync is pending.

## Relationship to Library

`library/{requirement_id}/**` is a **requirement-level DocFlow workspace** managed by AI SDLC standard library. It is independent of specs run lifecycle. A simple requirement may only produce `library/` artifacts without ever generating specs. A complex requirement that goes through Speckit pipeline will have both `specs/` and `library/` artifacts.
